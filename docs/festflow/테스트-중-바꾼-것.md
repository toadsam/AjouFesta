# 테스트하다 불편해서 바꾼 것

2026 가을축제 "바람"(10.07 ~ 10.08)을 앞두고, 직접 눌러 보면서 불편했던 점과 그래서 바꾼 것을 적어 두는 기록이다.
커밋 메시지는 "무엇을 바꿨는지"를 적고, 이 문서는 "왜 바꿨는지"를 적는다.

## 적는 법

- 테스트 중에 불편해서 바꾼 것이 생기면, 커밋할 때 이 문서 맨 위(가장 최근)에 한 칸을 추가한다.
- 한 칸에는 **불편했던 점 → 바꾼 것 → 커밋**을 적는다. 고민했지만 바꾸지 않은 것은 맨 아래 "바꾸지 않기로 한 것"에 이유와 함께 적는다.
- 암호 · 운영 키 · 계좌 같은 값은 적지 않는다(이 저장소는 공개다).

### 요리사 창을 메뉴별로 — 주방 4곳이 각자 메뉴만 보고, 메뉴마다 '완료'

- **상황**: 주점 주방이 메뉴별로 4곳(삼겹살 · 두부김치 · 짜파게티 · 어묵탕)으로 나뉘어 각 주방은 맡은 요리만 한다고 총학이 알려 옴(2026-10-06 밤). 요리사 창은 하나였고 '완료'가 주문 단위라, 두부김치 2 · 어묵탕 1 주문을 어느 주방이 완료할지 정할 수 없었다.
- **바꾼 것**: ① 서버 — 주문 줄(메뉴)마다 완료 시각(`booth_order_items.done_at`)을 둠. 새 API `PUT /api/ops/booth/{id}/orders/{orderId}/items/{lineNo}/done`. 첫 줄이 끝나면 조리 중(PREPARING), 모든 줄이 끝나면 서버가 서빙할 것(READY)으로 올림. 입금 확인 전 · 끝난 주문은 거절, 같은 줄을 두 번 눌러도 그대로. 주방 둘이 같은 주문의 다른 줄을 동시에 눌러도 마지막 줄을 놓치지 않게 주문 행을 잠그고 처리(`findByIdAndBoothIdForUpdate`). 콘솔에서 '준비 완료'를 대신 누르거나 서빙이 끝나면 남은 줄도 모두 완료로 적음. ② 요리사 창(`/ops/booth/:id/kitchen`) — 처음에 맡은 메뉴를 고르고(`?menu=메뉴이름`, 한 주방이 다 만들면 `?menu=all`), 그 메뉴가 든 입금 확인 주문만 입금순으로. 카드에는 내 메뉴 몫만 크게 + '완료'(5초 되돌리기), 같이 나갈 다른 메뉴는 작게(끝난 건 ✓). '조리 시작' 버튼은 뺌(완료 하나만). 내 몫은 끝났는데 다른 주방이 남은 주문은 아래 '다른 주방 기다리는 중'에. 위쪽 메뉴 이름을 누르면 바꾸기. ③ 콘솔 — 조리 중 카드의 메뉴마다 ✓와 '메뉴 1/3 완료', 회색 버튼은 '준비 완료' 하나(남은 메뉴 모두 완료로). ④ 연습 서버 · 눌러 보는 매뉴얼(주점 · 포장 흐름) · 정적 매뉴얼 글을 같이 바꿈.
- **확인**: 서버 테스트 3개 추가(줄마다 완료 → 조리 중 → 서빙할 것, 콘솔 대신 누름, 메뉴 하나 주문), 전체 테스트 통과. 연습 서버에서 두부김치 2 · 어묵탕 1 주문 → 입금 확인 → 두부김치 주방 완료(콘솔 ✓ · 1/2, 손님 '조리 중') → 어묵탕 주방 완료(서빙할 것 · 손님 '준비 끝') 까지 눌러 봄.
